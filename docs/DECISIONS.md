# Decisions

One line per decision: what was chosen, why, and the alternative that was not taken.

| # | Decision | Why | Alternative |
|---|----------|-----|-------------|
| 1 | argparse for the CLI | standard library, no extra dependency to audit | click/typer |
| 2 | Network blocked with a Python audit hook (`sys.addaudithook`) installed by the CLI | the guard cannot be removed once installed and covers dependencies too, not just our own code | relying on code review that no module opens sockets |
| 3 | Event IDs are hashes of (file SHA-256, relative path, record start line and column); inserts fail loudly on a collision | stable across reruns, so findings are reproducible; two byte-identical input files must still yield distinct events (a test caught the earlier hash silently dropping the second copy) | autoincrement row ids |
| 4 | `--force` only replaces a case folder containing nothing but TenantTrace's own files | avoids deleting an analyst's unrelated files by mistake | wiping the folder unconditionally |
| 5 | The case folder may not sit inside the input folder | the tool would otherwise hash and parse its own outputs | excluding it silently |
| 6 | Venv built from the 64-bit Python 3.12 (`py -3.12`), not the `python` on PATH | the PATH interpreter on this machine is 32-bit | using the 32-bit interpreter |
| 7 | Format, retention and ATT&CK facts were researched from Microsoft Learn, Microsoft's doc repos, collector source and attack.mitre.org, and recorded with CONFIRMED / UNCONFIRMED tags in docs/sources/ | the brief forbids writing schemas and limits from memory alone | building from memory and hoping |
| 8 | The generator writes the documented 4-column Purview layout by default and the undocumented 8-column layout in one scenario; the parser accepts both | only the 4-column layout is documented, but newer exports are reported to differ | supporting one layout only |
| 9 | Sign-in exports in the corpus reach back at most 30 days (P1/P2 retention) | a longer sign-in history would contradict the reference table and teach the gap analysis wrong expectations | 45-day sign-in exports |
| 10 | `ttcorpus` is a separate package that may not import `tenanttrace` (enforced by a test), and `docs/sources/layouts.yaml` is a third, hand-written transcription the generator is tested against | the tests should compare independent readings of the documentation, not the tool with itself | generator reusing parser constants |
| 11 | Generated Exchange mailbox `SessionId` values differ from the Entra session ID; the Entra session appears only in `AppAccessContext.AADSessionId` | Microsoft confirms only the AppAccessContext mapping; the parser must not rely on the unconfirmed one | making both equal |
| 12 | About 30% of baseline MailItemsAccessed Sync records are generated without AppAccessContext | Microsoft notes identifiers are missing on some aggregated Exchange entries; the inference path of session linking must be exercised | always including identifiers |
| 13 | The PowerShell UAL export is generated unsorted, UTF-16 LE with BOM and a `#TYPE` line | ReturnLargeSet output is unsorted; UTF-16 and preamble lines are what trips real parsers | a tidy UTF-8 file |
| 14 | invictus-ir/o365_dataset was not added | it is a 7z archive of real incident data that would need extraction tools and a privacy review | adding it unreviewed |
| 15 | The Splunk attack_data samples (Apache-2.0) were added with the full licence text | small, permissively licensed real-shape UAL and Azure Monitor sign-in records for parser tests | no third-party data |
| 16 | Formats are detected by content (header columns or first JSON record), each parser scoring 0-100 with a reason; the chosen parser, the reason and every score go to the processing log | collectors and analysts rename files; Microsoft lets users name downloads | trusting file names |
| 17 | Interactive vs non-interactive for CSV sign-in rows comes from the file name when no column says so, defaulting to interactive, and the basis is stored on every event | the CSV has no documented column for it; the JSON carries `isInteractive` / `signInEventTypes` | guessing from token type or client app |
| 18 | Record hashes are over the decoded record text re-encoded as UTF-8; each event also stores its line and column span so `read_spans` can re-read and re-hash it | the same record hashes the same in UTF-16 and UTF-8 exports, and byte offsets are not meaningful for UTF-16 | byte ranges only |
| 19 | A UAL record with an operation TenantTrace does not map is kept as an event of category `other` and counted per operation in the manifest; a record that cannot be read at all goes to the `unrecognised` table with its reason, line span and hash | nothing is dropped silently, and analysts can see exactly which operations the tool ignores | dropping unknown operations |
| 20 | UAL copies of Entra sign-ins (UserLoggedIn/UserLoginFailed) are linked to the Entra record when account, IP and outcome match within 5 seconds; the Entra record stays primary | Microsoft says correlationId is not a join key, so a conservative attribute match is used and its basis recorded | counting both, or joining on correlationId |
| 21 | Sign-in outcome comes from the error code (0 = success) or the CSV Status column; no "interrupted" codes are inferred | Microsoft documents Success/Failure/Interrupted only as UI values; inventing an error-code list would be unsupported | a remembered list of interrupt codes |
| 22 | STS logon (UserLoggedIn) outcome is taken from ErrorNumber/ErrorCode, never from ResultStatus | Microsoft documents that ResultStatus reflects the HTTP call for these records | ResultStatus |
| 23 | All `ual_*` sources inherit the period of the unified audit log export they came from; truncation, early end, retention and quiet periods are judged once for the export ("ual") and list the sources they affect | an export that covers a month but has no MailItemsAccessed says something about auditing, not about the export | judging each record type's first and last record as if it were its own export |
| 24 | Sources are marked `continuous` or `sparse` in the reference table; only continuous sources can be "auditing absent" or "absent for the user", and a sparse source with no records is reported as supplied-with-no-records | directory changes and inbox-rule cmdlets are rare, so their absence is normal; mail access and sign-ins are daily | treating any empty record type as a gap |
| 25 | Quiet periods, late starts and early ends are judged against each source's own hour-of-day rhythm (weekday and weekend separately): a silence counts only if the rhythm predicts at least 10 records for it and the other sources kept at least half their usual volume | fixed thresholds flag every night and weekend for bursty sources such as interactive sign-ins | fixed-hour thresholds |
| 26 | A retention cut is matched to a documented retention period when the first surviving record is no earlier than the cut-off and the rhythm predicts almost no records between the cut-off and that record | the cut-off falls anywhere before the first surviving record, so a fixed tolerance on "reach" misfires around weekends | comparing reach to the retention period with a fixed tolerance |
| 27 | A missing source with a supplied alternative (Entra audit log vs the UAL's directory records; Entra sign-ins vs UAL sign-in copies) is not reported as a gap | the evidence is still there in the other source | reporting every absent source |
| 28 | Added a fifth degraded variant (two working days missing from the audit log export) | the brief lists quiet periods among the gaps to report, and only a degraded copy can test that | leaving quiet-period detection untested |
| 29 | The compromise window starts where the analyst says (`--window-start`); otherwise at the earliest baseline-independent indicator (rules marked `anchor`) minus 72 hours; otherwise 14 days before collection. The report states which method was used | "unusual" must be measured against history before the compromise, and an analyst may not know when it began | always requiring the analyst to supply it |
| 30 | A rule that needs history requires the account's records to reach back at least 14 days and 10 records before the window (sign-in history counted from the Entra sign-in logs only) | a short or location-less history (the UAL's sign-in copies have no country) cannot say what is unusual; the rule then reports it could not run | counting only days with activity, or using UAL sign-in copies |
| 31 | Rules run in two stages. Only access findings at probable or above mark IPs, sessions and tokens as attacker-linked for later rules, and the account's own baseline IPs are never marked | possible-level leads (a business trip) must not make the user's own later activity look malicious | propagating every finding |
| 32 | A session counts as replayed only when its own sign-ins imply impossible travel (or, without coordinates, two countries within an hour) | a traveller's laptop session legitimately appears in two countries days apart | any session seen in two countries |
| 33 | A finding's attacker indicators come only from its triggering events outside the account's baseline IPs | an impossible-travel pair contains the user's genuine sign-in too | all triggering events |
| 34 | The pivot ignores indicators that more than half of the tenant's accounts used before the window, user agents of the account's own browser family, and application IDs except from consent and app-access findings | a proxied corporate browser string or a first-party app ID would otherwise list the whole tenant; an attacker IP that hit many accounts during the attack must still count | unfiltered indicators |
| 35 | Rules that only link activity to attacker access (TT-MAIL-004) report "could not be assessed" when no sign-in rule could run | "nothing found" would be wrong when the link could never be made | reporting zero findings |
| 36 | Added TT-MAIL-005 (mailbox read over IMAP/POP from an unfamiliar IP) and let TT-SIGNIN-006 use the UAL's sign-in copies | mail collection and password spraying stay visible from the audit log alone when sign-in logs are missing | sign-in-only detection |
| 37 | On Windows, inputs and generated corpus folders are opened through extended-length (`\?\`) paths | collector folder names push paths past 260 characters; the system-wide long-path setting is a system change the tool must not require | failing on deep collector folders |
| 38 | The evaluation harness is a third package, `tteval`, which imports both the generator and the tool | the generator must stay independent of the tool; something has to bring them together | evaluating inside the generator |
